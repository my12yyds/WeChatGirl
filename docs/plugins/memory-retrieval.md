# 档案检索助手

版本：1.2.1 · 可选插件，按需安装

[返回插件目录](README.md) · [下载单独插件包](https://github.com/my12yyds/WeChatGirl/releases/download/v0.5.7/memory-retrieval-1.2.1.zip)

## 适合做什么

按关键词与可选本机语义模型从完整档案中寻找原文证据。

从已授权聊天的历史中寻找相关原文，例如把“猫叫什么”和“家里那只毛孩子”关联起来。支持关键词和可选本机语义模型，返回证据而不凭空补写记忆；按微信账号、聊天和真实人物隔离。首次完整检索会后台建立索引，可查看进度。关闭插件保留索引，但停止使用。

## 第一次配置

1. 在能力目录导入该插件，或导入总包。
2. 启用历史读取，选择聊天；向量实验还需本机嵌入环境和对应权限。
3. 在“插件与聊天”选择具体好友或群聊，不需要的范围保持关闭。
4. 保存并检查插件状态，先用简单请求验证；升级宿主接口后按提示完整重开DSH。

## 使用例子

“之前说过我家猫叫什么？”；首次建索引时使用进度工具确认完成情况。

## 权限与数据

- 读取当前聊天历史
- 独立调用当前模型（会产生消耗）
- 调用本机嵌入模型（向所选本机服务提供当前聊天片段）

关闭插件停止后续调用，已有本机数据保留。总包导入不会启用插件、放宽聊天授权或覆盖已安装插件。

## 配置选项

| 配置 | 默认值 | 范围或选择 | 说明 |
| --- | --- | --- | --- |
| 使用当前模型重排候选（产生消耗） | false | 开 / 关 | 仅近期检索模式生效：让当前聊天模型对候选重新排序，可能增加费用和等待；关闭则直接使用关键词排序，模型失败会回退。 |
| 检索近期记录条数 | 100 | 10–100 | 关闭完整档案检索时生效。只读取当前聊天最近这些条消息；调大可覆盖更多近期话题，但不代替完整档案。 |
| 候选条数 | 20 | 4–30 | 仅近期模式的候选数量。模型重排时从这些原文里选证据；越多通常越慢。 |
| 返回证据条数 | 4 | 1–8 | 一次最多交给聊天模型多少条证据。建议先保留4；过多会增加上下文占用。 |
| 实验：启用本机向量混合检索 | false | 开 / 关 | 默认关闭。开启后调用本机嵌入服务理解近义表达，需要额外模型环境和model_embed权限；不可用时回退关键词，不自动上传到云端。 |
| 本机嵌入服务地址 | "http://127.0.0.1:19884/v1/embeddings" | 最多200字符 | 本机兼容/v1/embeddings的HTTP地址，只允许127.0.0.1。内置服务默认19884端口；地址改变会使用独立索引，首次需重新建立。 |
| 嵌入模型 ID | "multilingual-minilm-l12-v2-q8" | 最多100字符 | 内置模型填multilingual-minilm-l12-v2-q8。外接本机服务填实际模型ID；只修改名字不会下载模型。切换模型会建立独立向量索引。 |
| 语义分数权重 | 0.65 | 0–1 | 范围0–1，默认0.65。越高越重视语义接近，越低越重视原文关键词；仅向量服务正常时生效，时间新近度另作少量排序参考。 |
| 检索完整聊天档案（后台索引） | true | 开 / 关 | 开启则在后台按批索引完整聊天档案，不限近期100条；首次可能暂时没有结果，稍后重试或用索引工具看进度。关闭后使用近期检索。 |
| 每个聊天索引分片上限 | 50000 | 100–100000 | 默认50000个文本分块，每块约500字符。一条长消息可能拆多块；达到上限会标明受限。不是模型上下文长度，也不会删除原始聊天。 |
| 语义召回最低相似度 | 0.25 | 0–1 | 0–1，默认0.25；没有关键词命中时，语义相似度至少达到此值才返回。过高容易漏记，过低可能混入无关资料。 |

## 限制与排查

检索先按账号、聊天及人物过滤；向量不可用时回退关键词，不会自动上传档案到云端。

- 状态“已安装，尚未启用”：检查插件总开关、权限和聊天范围。
- 状态“等待新版宿主”：准备配置后从托盘完整重开DSH。
- 模型或本地环境报错：先在对应功能页做连接检测或本机试听，不要重复发送真实消息试错。
- 不要在公开问题报告中贴令牌、Cookie、聊天原文或私人路径。
